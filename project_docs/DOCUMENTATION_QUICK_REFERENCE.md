# Haive Documentation Quick Reference

**Last Updated**: January 2, 2025

## Build Commands

```bash
# Basic build (fast, development)
poetry run nox -s docs_fast

# Full build (slower, production)
poetry run nox -s docs

# Clean previous build
poetry run nox -s docs_clean

# Build and serve with auto-reload
poetry run nox -s docs_serve

# Open built docs in browser
poetry run nox -s docs_view

# Check for broken links
poetry run nox -s docs_check

# Check documentation coverage
poetry run nox -s docs_coverage
```

## Key Files

### Configuration
- `docs/source/conf.py` - Main Sphinx configuration
- `docs/source/conf_namespace.py` - Namespace package discovery
- `noxfile.py` - Build system configuration

### Documentation Structure
- `docs/source/index.rst` - Main landing page
- `docs/source/api/index.rst` - API reference (autogenerated)
- `docs/source/guides/` - User guides and tutorials

### Extensions
- `docs/source/_extensions/mock_handler.py` - Import mocking
- `docs/source/_templates/` - Custom templates

## Autosummary

### Enabled Features
- ✅ Automatic API documentation generation
- ✅ Namespace package support
- ✅ Recursive module discovery
- ✅ Cross-reference linking

### Configuration
```python
# In conf.py
autosummary_generate = True
autosummary_generate_overwrite = True
autosummary_imported_members = False
```

### Usage in RST Files
```rst
.. autosummary::
   :toctree: generated
   :recursive:

   haive.core
   haive.agents
```

## Namespace Packages

### Structure (PEP 420)
```
packages/haive-core/src/haive/     # No __init__.py
packages/haive-agents/src/haive/   # No __init__.py  
packages/haive-tools/src/haive/    # No __init__.py
```

```python
# Correct imports for documentation

```

## Troubleshooting

### Common Issues

1. **Import Errors During Build**
   - Check `docs/source/conf_namespace.py` is working
   - Verify all package paths in `sys.path`
   - Check mock_handler.py for missing dependencies

2. **Autosummary Not Generating**
   - Ensure `autosummary_generate = True`
   - Check module paths are correct
   - Look for import errors in build output

3. **Missing Dependencies**
   - Add to `autodoc_mock_imports` in conf.py
   - Or add to mock_handler.py EXTERNAL_DEPENDENCIES

### Debug Commands
```bash
# Test namespace package discovery
poetry run python -c "import haive; print(haive.__path__)"

# Check specific module import
poetry run python -c "from haive.core import engine; print('OK')"

# Verbose build with errors
cd docs && poetry run sphinx-build -v -b html source build/html
```

## Best Practices

### Adding New Modules
1. Ensure module follows namespace package structure
2. Add to appropriate autosummary list in `api/index.rst`
3. Add any new dependencies to mock lists if needed

### Writing Documentation
1. Use Google-style docstrings (Napoleon enabled)
2. Include type hints (autodoc_typehints enabled)
3. Add examples in docstrings

### Performance
- Use `docs_fast` for development (skips some checks)
- Use `docs_clean` before important builds
- Consider excluding large/slow modules if needed

## Integration

### CI/CD
The documentation system is designed to work in CI environments:
- All dependencies mocked appropriately
- No external services required
- Deterministic builds

### ReadTheDocs
Configuration compatible with RTD:
- Uses poetry for dependency management
- Proper requirements specification
- Mock system handles missing deps
