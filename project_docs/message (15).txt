# Backend WebSocket API Integration Guide

## Overview

This guide provides comprehensive documentation for integrating with the Staidium Assistant UI backend WebSocket API. The system supports multiple agent types, real-time streaming, tool calling, and artifact generation using both Socket.io and native WebSocket protocols.

## Architecture

### Core Components

1. **Socket Server** (`socket-server/server.ts`) - Socket.io server for real-time communication
2. **Agent Handler** (`socket-server/agent-handler.ts`) - Manages agent interactions and message routing
3. **Assistant UI Frontend** - React components with assistant-ui library integration
4. **WebSocket Proxy** - Bridges Socket.io and native WebSocket interfaces

### Technology Stack

- **Backend**: Node.js + Express + Socket.io + TypeScript
- **Frontend**: Next.js 14 + React + TypeScript + assistant-ui
- **Package Manager**: pnpm
- **WebSocket**: Socket.io for real-time bidirectional communication

## Installation & Setup

### Backend Setup

```bash
# Navigate to socket server directory
cd socket-server

# Install dependencies
pnpm install

# Development mode
pnpm dev

# Production build and start
pnpm build
pnpm start
```

### Environment Configuration

Create `.env` file in `socket-server/` directory:

```env
PORT=8001
CLIENT_URL=http://192.168.2.13:3000
API_BASE_URL=http://192.168.2.13:8000/api
```

### Frontend Configuration

The frontend connects to the WebSocket server at:
- **Socket.io**: `http://192.168.2.13:8001`
- **WebSocket**: `ws://192.168.2.13:8000/ws/chat/{thread_id}`

## API Reference

### Connection Endpoints

#### Socket.io Connection
```javascript
const socket = io('http://192.168.2.13:8001', {
  path: '/socket.io',
  transports: ['websocket', 'polling']
});
```

#### Native WebSocket Connection
```javascript
const ws = new WebSocket('ws://192.168.2.13:8000/ws/chat/thread-123');
```

### Agent Types

The system supports four specialized agent types:

- `chat_agent` - General conversation and assistance
- `summarizer_agent` - Content summarization and analysis  
- `code_agent` - Code generation and programming assistance
- `data_agent` - Data analysis and visualization

### Message Protocol

#### Client → Server Messages

##### Agent Request (Socket.io)
```json
{
  "type": "agent_request",
  "agent_id": "chat_agent",
  "content": "User's message here",
  "thread_id": "thread-uuid",
  "timestamp": "2024-01-01T00:00:00Z",
  "token": "auth-token-optional"
}
```

##### Agent Request (WebSocket)
```json
{
  "type": "agent_request", 
  "agent_id": "code_agent",
  "content": "Write a Python function to calculate fibonacci",
  "thread_id": "thread-uuid",
  "timestamp": "2024-01-01T00:00:00Z"
}
```

##### Stop Processing
```json
{
  "type": "stop",
  "thread_id": "thread-uuid"
}
```

##### Reload/Regenerate
```json
{
  "type": "reload",
  "agent_id": "data_agent", 
  "content": "Regenerate the last response",
  "thread_id": "thread-uuid"
}
```

#### Server → Client Responses

The server streams responses in the following sequence:

##### 1. Message Start
```json
{
  "type": "message_start",
  "thread_id": "thread-uuid"
}
```

##### 2. Thinking Process (Optional)
```json
{
  "type": "thinking",
  "content": "Analyzing the request and determining approach...",
  "thread_id": "thread-uuid"
}
```

##### 3. Tool Calls (Optional)
```json
{
  "type": "tool_call",
  "tool_call_id": "call-123",
  "field": "web_search",
  "writes": {
    "query": "latest AI developments"
  },
  "thread_id": "thread-uuid"
}
```

##### 4. Tool Results (Optional)
```json
{
  "type": "tool_result", 
  "tool_call_id": "call-123",
  "result": {
    "results": [
      {
        "title": "AI News Article",
        "url": "https://example.com",
        "snippet": "Latest developments in AI..."
      }
    ]
  },
  "thread_id": "thread-uuid"
}
```

##### 5. Content Streaming
```json
{
  "type": "content",
  "content": "Here's what I found about AI developments...",
  "thread_id": "thread-uuid"
}
```

##### 6. Artifacts (Optional)
```json
{
  "type": "artifact",
  "field": "generated_code",
  "content": {
    "type": "code",
    "language": "python", 
    "title": "Fibonacci Calculator",
    "content": "def fibonacci(n):\n    if n <= 1:\n        return n\n    return fibonacci(n-1) + fibonacci(n-2)"
  },
  "thread_id": "thread-uuid"
}
```

##### 7. Final Message
```json
{
  "type": "message",
  "message": {
    "id": "msg-uuid",
    "role": "assistant", 
    "content": "Complete response with the code above...",
    "thread_id": "thread-uuid",
    "created_at": "2024-01-01T00:00:00Z"
  }
}
```

## Socket.io Event Reference

### Client Events (Emitted by Frontend)

- `agentRequest` - Send agent request message
- `agentMessage` - Send generic agent message
- `stop` - Stop current processing
- `getProviders` - Request LLM provider list
- `getModels` - Request available models
- `disconnect` - Client disconnection

### Server Events (Emitted by Backend)

- `agentResponse` - Stream agent response data
- `providers` - Send LLM provider data
- `models` - Send model data

## Frontend Integration

### Using with assistant-ui

```tsx
import { AssistantRuntimeProvider } from "@assistant-ui/react";
import { createLangGraphRuntime } from "@/lib/assistant-ui/langgraph-runtime";

const runtime = createLangGraphRuntime({
  threadId: "thread-123",
  agentId: "chat_agent", 
  onThinking: (thought) => console.log(thought),
  onArtifact: (key, artifact) => setArtifacts(prev => ({...prev, [key]: artifact}))
});

// Use with provider
<AssistantRuntimeProvider runtime={runtime}>
  <Thread />
</AssistantRuntimeProvider>
```

### Socket.io Client Usage

```javascript
import { io } from 'socket.io-client';

const socket = io('http://192.168.2.13:8001');

// Send agent request
socket.emit('agentRequest', {
  type: 'agent_request',
  agent_id: 'chat_agent',
  content: 'Hello, how can you help me?',
  thread_id: 'thread-123'
});

// Listen for responses
socket.on('agentResponse', (data) => {
  console.log('Agent response:', data);
});
```

## Performance Considerations

### Connection Management
- **Socket.io**: Automatic reconnection with exponential backoff
- **WebSocket**: Manual reconnection handling required
- **Connection Pool**: Reuse connections per thread

### Message Batching
- Content chunks can be sent rapidly for smooth streaming
- Batch non-critical updates to reduce overhead
- Buffer tool results for complex processing

### Resource Cleanup
- Close connections when threads are inactive
- Clean up event listeners on component unmount
- Cancel ongoing requests when switching agents

## Troubleshooting

### Common Issues

1. **Connection Refused**
   - Check if server is running on correct port
   - Verify CORS configuration
   - Ensure firewall allows connections

2. **Message Not Streaming**
   - Check network connectivity
   - Verify message format
   - Monitor server logs for errors

3. **Agent Not Responding**
   - Validate agent_id parameter
   - Check agent handler configuration
   - Verify backend API connectivity

## Migration from WebSocket to Socket.io

### Code Changes Required
```javascript
// Old WebSocket code
const ws = new WebSocket('ws://192.168.2.13:8000/ws/chat/123');
ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
};
ws.send(JSON.stringify(message));

// New Socket.io code  
const socket = io('http://192.168.2.13:8001');
socket.on('agentResponse', (data) => {
  // data is already parsed
});
socket.emit('agentRequest', message);
```

### Benefits of Socket.io
- Automatic reconnection
- Fallback to HTTP polling
- Built-in heartbeat mechanism
- Event-based messaging
- Better error handling
